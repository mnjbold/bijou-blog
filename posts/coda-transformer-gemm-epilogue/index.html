CODA: Rewriting Transformer Blocks as GEMM-Epilogue Programs (arXiv)

news 2 min read
B

Transformer training is hitting a memory wall, and a new paper from a team of researchers introduces CODA — a GPU kernel abstraction that fuses nearly all non-attention operations into GEMM-plus-epilogue programs, keeping data on chip and dramatically reducing memory bandwidth bottlenecks.

Modern Transformer training systems are built around highly optimized dense linear algebra (GEMM) kernels, but a surprising amount of time is actually spent on "glue" operations — normalizations, activations, residual updates, and reductions that shuttle large intermediate tensors through global memory while performing minimal arithmetic. As GPU compute speed outpaces memory bandwidth, this data movement overhead is becoming the dominant bottleneck in production training stacks.

What CODA Does

CODA is based on a simple but powerful insight: many of the operators that sit between GEMM layers in a Transformer (LayerNorm, GELU, residual add, etc.) can be algebraically reparameterized to execute while the GEMM output tile is still on chip, before it is ever written to memory.

The abstraction works like this:

  • A GEMM mainloop runs the dense matrix multiply as usual
  • A set of composable epilogue primitives handle scaling, reductions, pairwise transformations, and accumulations — all on the same SRAM tile
  • This constrained interface preserves the performance characteristics of expert-written GEMMs while being expressive enough to cover nearly all non-attention computation in both forward and backward passes of a standard Transformer block

Key Results

  • CODA kernels achieve performance competitive with (and in some cases better than) hand-tuned CUDA kernels across representative Transformer workloads
  • The abstraction is simple enough that both human and LLM authors can produce high-performance kernels, suggesting a path toward automated kernel generation
  • Memory footprint is reduced because intermediate tensors never leave the compute tile

Key Takeaways

  • Memory-bound "glue" operators now dominate Transformer training time; CODA fuses them into GEMM epilogues to eliminate data movement
  • The GEMM-plus-epilogue abstraction is expressive enough to cover normalizations, activations, residuals, and reductions across forward and backward passes
  • Both human and LLM-generated CODA kernels achieve high performance — hinting at a future where LLMs write optimized training kernels
  • This approach directly tackles the growing gap between compute throughput and memory bandwidth in modern GPUs
  • CODA is open source and available for experimentation

Why It Matters

As model scales continue to grow, the memory wall is becoming the primary limiter of training efficiency. CODA offers a principled, practical approach that doesn't require exotic hardware or rewriting the entire stack — it's a compiler-friendly abstraction that could find its way into PyTorch, JAX, and custom training frameworks. For anyone training large Transformers, this is research worth watching closely.
